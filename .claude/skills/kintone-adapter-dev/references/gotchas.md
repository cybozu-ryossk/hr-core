# 実運用の落とし穴

外部システムアプリ化（Agent 方式）の Adapter を作るときに踏みやすい仕様・挙動。設計段階で織り込む。

## Count が呼ばれないことがある
Select の結果件数が `limit`（maxCount）未満だと、Agent が「全件取得済み」とみなして Count を省略する。
- 影響: 全件ヒットしないケースで、Count に依存したページング・件数表示が動かない（0 件や未表示になる）。
- 対策: **件数を Count 前提で組まない**。UI 側は `results.length` で代替できる設計にする。
  Agent の内部ロジックは非公開なので、事象ベースで実装を合わせるしかない。

## 一覧に表示していないフィールドはデータ交換されない
kintone の一覧画面（ビュー）に表示設定されていないフィールドは、Adapter が値を返しても kintone 側で
受け取られない。Select の `fields` にも、一覧に無いフィールドは載ってこない。
- 影響: 「Adapter は返しているのに画面に出ない」というデバッグの典型原因。
- 対策: 参照したいフィールドは一覧に含める。見せたくないだけなら一覧に入れて CSS/JS で隠す。

## アクセス権が無い
kintone 標準のアクセス権（レコード単位・フィールド単位）は外部システムアプリ化では機能しない。
テナント内の全ユーザーが全レコードを見られる状態になる。
- 対策: 制御が要るなら **Adapter 側（外部システム側）で実装**する。Context の `user.user_id` /
  `user.user_code` を使って返すデータを絞る。申請→承認で動的に権限を付ける運用にも応用できる。
- 注意: user_code はデフォルトで「送信しない」設定。使うならコネクタのコンテキスト送信設定を確認。

## record_id_type は後から変えられない
コネクタ接続時に GetCapability の `record_id_type` が保存され、**以後変更不可**。数値か文字列かを最初に確定する。
文字列 ID は `^[a-zA-Z0-9_-]{1,100}$`。違反値は `CB_VA01`。文字列 ID ではコメント・編集履歴が使えない。

## 未宣言の RPC を呼ぶと unimplemented
GetCapability で `false` にした（＝提供しないと宣言した）RPC は kintone から呼ばれない。逆に、
サポートすると宣言したのに実装が無いと `unimplemented` エラーになる。宣言と実装を必ず一致させる。

## Search AI は現状使えない
Search RPC を実装しても、kintone 側の検索 AI 機能が未実装のため現時点では使われない。
実装の優先度は低い（将来アプリ内検索で使う想定）。

## and/or 混在の絞り込みは非対応
`match_operator` は全体で 1 つ（AND か OR）。and と or の混在（一階層以上）は現状の kintone では作れない。
グラフ要素クリックや関連レコード一覧の「さらに絞り込む」で OR 指定するとエラーになることがある。

## 通常アプリで使えない機能が多い
プロセス管理・通知・Webhook・アクセス権・カテゴリー・変更履歴・CSV/Excel 入出力・カーソル API・
`updateKey` 指定の更新・アプリの動作テストなどは使えない/制限される。外部側でこれらに相当する要件が
ある場合は Adapter 側の設計で吸収するか、要件から外す判断が要る。

## レスポンス 4MB 制限
Adapter のレスポンスが 4MB を超えると `GAIA_RS01`。大きな Select は `limit` を守り、1 レコードを軽くする。
